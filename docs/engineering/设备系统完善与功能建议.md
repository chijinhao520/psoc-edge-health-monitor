# 设备系统完善与功能建议

2026-10-28。本轮重点为设备本体的测量闭环、故障恢复及状态可见性，网页作为配套。

## 已落实到设备代码

| 能力 | 使用行为与边界 |
|---|---|
| 取消测量 | 等待手指、稳定和测量阶段的按钮改为“取消测量”。点击后撤销旧结果，等待采集核确认，再显示“已取消”；取消确认期间不重复下发 |
| 超时与重试 | 单次测量总上限90秒；请求10秒未确认显示失败并允许重试。采集核停更撤有效，完成结果过期显示“数据已失效”，不再持续显示成功 |
| 启动缺设备仍可恢复 | ECG、GSR、MLX、SHT初始化失败保留任务，以2秒间隔重试；共享mux的延迟初始化加互斥，避免多任务同时创建不同句柄 |
| PPG掉线/掉电恢复 | 单次探测替代运行中的长阻塞重试；缺失源有退避；每窗核对FIFO、工作模式、采样率与LED配置。通信错误或配置复位触发重新初始化，活动源恢复不会沿用旧聚合窗口 |
| 共享总线更少阻塞 | MLX上电300ms等待移到mux锁外，后台探测不再阻塞其他采集300ms；长期ECG/GSR失败增加退避，避免刷日志及占总线 |
| ADC与GSR有效性 | ADC转换超时直接失败，防止读取上一通道的残值。GSR通信失败/断流/零码/负值/饱和/非有限输入清个人基线；恢复后重新学习 |
| 屏幕检测状态 | 设置页新增采集核、心率/血氧、红外温度、环境温湿度、GSR、心律分析和HRV状态；WiFi与数据上传连接分开显示。监测页状态灯由真实采集核心跳驱动 |
| 状态文案与量纲 | 区分传感器未连接、采集核停更、等待超时、取消和过期；温度卡改“红外温度”，BMR单位改为kcal/h。新增中文已通过现有字库覆盖检查 |

“数据有效”只说明当前软件链路接受了这项数据，不证明精度或诊断价值。设置页不会把“未测或失效”武断解释为传感器损坏。

指令标记升级为CMD2；标量/波形保持SDA2/PPG2/ECG2布局。必须成套更新M33/M55；本轮未烧录。开机约5秒PPG任务才开始受理命令，计入10秒确认等待范围。恢复探测成功时仍需短暂配置时间，ECG连续窗可能因此重建。

## 上板验收顺序

1. 不接拓展板启动，再接回；观察各采集任务是否恢复，确认不会出现双mux实例或永久退出。
2. 单PPG/双PPG分别测试，依次拔掉主路、副路；对正在使用的一路断电再接回，确认旧窗口不进入新结果。
3. 在等手指、稳定期、采样期、快完成时分别按取消；再立即重测，确认结果、语音、云端均不串轮次。
4. 暂停采集核、模拟通信失败、长时间无手指；检查状态灯、失败提示、10秒确认等待和90秒总上限。
5. 断开GSR再接回，确认先重新学习；拔掉MLX/SHT检查其无效状态以及对ECG/PPG连续性的影响。
6. WiFi断开再连接，区分本机数据采集与上传状态；确保离线期间设备测量与取消仍正常。

## 下一批值得加的本机功能

| 优先级 | 功能 | 实施前需要确认 |
|---|---|---|
| P1 | 引导式体检流程：按步骤提示手指/电极、显示各项准备进度、统一结束报告 | ECG与PPG同时工作时实测有效率；各项最低连续窗口和失败后跳过策略 |
| P1 | 本机故障记录：保存最近几次断流、通信失败、恢复和取消原因，便于售后/比赛排障 | 环形记录容量、掉电保存必要性；日志不阻塞实时采集 |
| P1 | 本机测量历史：断网也可回看最近几次完成结果、测量时间与失效原因 | 可用存储、断电写入一致性、擦写寿命；无RTC时明确相对时间 |
| P2 | 设备上的信号质量指导：提示接触不足、波形饱和、采样中断，并显示本次使用的PPG来源 | 根据实板原始波形校准门限，不能用猜测“置信百分比”代替验证 |
| P2 | 用户资料与BMR估计 | 明确人口学资料、单位和模型训练契约；估计值与直接测量值区分，血糖仍需独立验证 |

以上是后续候选，本轮没有把尚未实现的功能写成已上线。优先补齐体检流程、故障可追溯和离线能力，再考虑增加新的生理估计指标。
